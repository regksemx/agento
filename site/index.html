A plugin and a CLI for Claude Code. Open source, Apache-2.0.Alpha, October 2026

Two thirds of my Claude Code bill was the same context, read again.

agento shows where your Claude Code money goes, then picks a cheaper model only at the moments when switching costs nothing: when a task starts, after /clear, and inside subagents. It never changes the model in the middle of a task.

The bill is re-reading, not writing

Claude Code sends the whole conversation with every step. The prompt cache makes each re-read cheap, but an agent takes hundreds of steps, and every one of them re-reads everything before it. On a long task that re-reading is most of what you pay for.

An independent study of Claude Code on SWE-bench found the same shape: 87% of the bill was prompt cache, while tool output and file reads were about 6%.2 So a tool that trims tool output is working on the smallest line of the invoice. In that study, one “token compression” tool raised the total by 48%.

2“Token Reduction Is Not Cost Reduction”, arXiv 2607.12161. 44% cache writes, 35% cache reads, 10% output.

Why it never switches mid-task

The cache belongs to one model. Switch from Opus to Sonnet halfway through and Sonnet has to write the whole context again. On a 100k context that is $0.25 of cache writes instead of a $0.02 read. Sonnet then saves about two cents a step, so the switch pays for itself after roughly ten more steps, and only if Sonnet needs no extra ones.

So agento makes one decision per task, at a clean point, and shows it to you. A clean point is the start of a session, the first prompt after /clear or a compaction, a prompt after the cache has gone cold, or a new task you mark with /agento new. During the task it routes subagents, which have their own cache and can run on Haiku or Sonnet for free, and it flags an agent that fails the same test a third time. The arithmetic is on How it works.

What a judge thought of my month

I asked Claude Opus to read 560 of my finished Opus and Fable tasks and say which ones a cheaper model would have handled.

54%it said Sonnet or Haiku would have done (303 of 560).
41%of the time it picked too cheap, against my own labels.

The second number is why the first one is not a promise. On 34 tasks I labelled by hand, the judge agreed with me half the time and under-routed in 41% of cases.4 A judge’s opinion of a finished task is not a replay.

The first trained model did not pass

I distilled those labels into a small local model, multilingual-e5-small. A local daemon, agento-brain, serves it in about 6 ms.5 The rule for letting it choose the model is simple: on held-out tasks it may pick a model that is too cheap in at most 5% of cases. From the prompt alone, it could not.

5Median on an Apple-silicon Mac. The training box measured 8.1 ms at 128 tokens and 17.6 ms at 256 on its CPU.

So the model choice stays with the built-in rules and the student never makes it. Two of its other heads are good enough and are in use: whether to plan first (92% accurate), which brings up the hint to plan on Opus, and whether to start by exploring (76%), which tells the agent to send agento-scout first when orchestrator mode is on. Next I will try deciding after the first few steps of a task, when there is more to go on than the prompt.

Rules it keeps

  1. Never switch the main model mid-task. Only at a clean point, and only through a choice you can see.
  2. Never above your choice. It will not raise the model or effort you picked.
  3. Nothing silently. Every hint has a reason and an estimate; every automatic action can be undone.
  4. Fail-open. If agento errors or times out, Claude Code behaves as if it were not installed.
  5. Dollars, not tokens. Measured spend says “measured”. Savings always say “estimate”.
