Плагин и CLI для Claude Code. Открытый код, Apache-2.0.Альфа, октябрь 2026

Две трети моего счёта за Claude Code ушли на повторное чтение контекста.

agento показывает, на что уходят ваши деньги в Claude Code, и предлагает модель подешевле только там, где смена ничего не стоит: в начале задачи, после /clear и внутри субагентов. Посреди задачи он модель не меняет никогда.

Посмотреть, куда уходят деньги
npx agento-cc audit
Читает транскрипты, которые Claude Code и так хранит у вас на диске. Ничего никуда не отправляет. Нужен Node 20 или новее.
Добавить в Claude Code
/plugin marketplace add regksemx/agento
/plugin install agento@agento
Claude Code 2.1.287 или новее. Автопилот и оркестр включены; каждый выключается одним переключателем.

1API-эквивалент: по подписке за токены ничего не списывается. Расход проявляется в том, что недельный лимит кончается раньше.

Деньги уходят на перечитывание

На каждом шаге Claude Code отправляет модели весь разговор целиком. Кэш промптов делает такое перечитывание дешёвым, но агент делает сотни шагов, и каждый заново читает всё, что было до него. На длинной задаче именно это и составляет большую часть счёта.

Независимое исследование Claude Code на SWE-bench пришло к той же картине: 87% счёта пришлось на кэш промптов, а вывод инструментов и чтение файлов дали около 6%.2 Значит, инструмент, который ужимает вывод инструментов, работает с самой маленькой строкой счёта. В том же исследовании один инструмент «сжатия токенов» увеличил итоговую сумму на 48%.

2«Token Reduction Is Not Cost Reduction», arXiv 2607.12161. Запись в кэш 44%, чтение из кэша 35%, вывод 10%.

Почему он не меняет модель посреди задачи

Кэш принадлежит одной модели. Если на полпути перейти с Opus на Sonnet, Sonnet придётся заново записать весь контекст. При контексте 100k это $0,25 за запись в кэш вместо $0,02 за чтение. Дальше Sonnet экономит около двух центов на шаге, так что смена окупится примерно через десять шагов, и то если Sonnet не понадобятся лишние.

Поэтому agento принимает одно решение на задачу, в чистой точке, и показывает его вам. Чистые точки: начало сессии, первый промпт после /clear или сжатия контекста, промпт после того, как кэш остыл, и новая задача, которую вы отметили командой /agento new. Во время задачи он распределяет субагентов: у них свой кэш, и их можно запускать на Haiku или Sonnet бесплатно. А ещё он замечает агента, у которого один и тот же тест падает в третий раз. Подробный расчёт есть на странице «Как это работает».

Что судья сказал о моём месяце

Я попросил Claude Opus прочитать 560 моих завершённых задач, которые шли на Opus и Fable, и сказать, с какими справилась бы модель подешевле.

54%задач, по его мнению, решили бы Sonnet или Haiku (303 из 560).
41%случаев он выбирал слишком дешёвую модель по сравнению с моей разметкой.

Из-за второго числа первое нельзя считать обещанием. На 34 задачах, которые я разметил вручную, судья совпал со мной в половине случаев, а в 41% выбрал модель дешевле нужной.4 Мнение судьи о готовой задаче не заменяет повторного прогона.

4n = 34 ручные метки. Все графики с оговорками собраны на странице «Бенчмарки».

Первая обученная модель проверку не прошла

Я дистиллировал эти метки в маленькую локальную модель multilingual-e5-small. Её обслуживает локальный демон agento-brain, ответ занимает около 6 мс.5 Условие, при котором ей можно доверить выбор модели, простое: на отложенных задачах она может выбрать слишком дешёвую модель не больше чем в 5% случаев. По одному промпту у неё это не получилось.

Поэтому модель по-прежнему выбирают встроенные правила, а ученик в этом не участвует. Зато две другие его головы достаточно точны и уже работают. Первая решает, нужно ли сначала составить план (точность 92%), и если да, появляется подсказка спланировать задачу на Opus. Вторая решает, стоит ли начать с разведки (76%), и если да, а режим оркестратора включён, агент первым делом отправляет agento-scout. Дальше попробую принимать решение после первых нескольких шагов задачи, когда для него есть что-то кроме промпта.

Правила, которые он соблюдает

  1. Не менять основную модель посреди задачи. Только в чистой точке и только так, чтобы вы видели выбор.
  2. Не выше вашего выбора. Он не поднимет модель или effort, которые выбрали вы.
  3. Ничего втихую. У каждой подсказки есть причина и оценка, любое автоматическое действие можно отменить.
  4. Fail-open. Если agento упал или не уложился по времени, Claude Code работает так, будто его нет.
  5. Доллары, а не токены. Измеренный расход помечен «факт», экономия всегда помечена «оценка».

Все семь правил, каждое с примером, описаны на странице «Как это работает».
