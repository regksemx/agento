A plugin and a CLI for Claude Code. Open source, Apache-2.0.Alpha, October 2026

One decision per task, made where it is free.

agento is a Claude Code plugin. Its hooks see every prompt and every model request, and can draw a status line, one banner above the prompt and a pane. It makes one model decision when a task starts, then stays out of the way: it routes subagents, watches for loops and counts the money.

Clean points

A model is cheap to change only when there is no warm cache to lose. agento treats four moments as the start of a task: the first prompt of a new session, the first prompt after /clear or a compaction, a prompt after the cache has gone cold, and a task you mark yourself with /agento new.1 Inside a task the verdict is still computed for the ledger, and nothing is acted on.

1The cache lives 5 minutes or 1 hour, depending on how the request asked for it. agento reads the lifetime from each response rather than assuming one.

By default agento applies the choice itself, but only for that one task, only where the switch is free, and it says so with an undo button. The next clean point decides again. When the turn ends, a short receipt says what the task cost and what saved money. With /agento autopilot off you get a hint with its reason and an estimate instead, and you decide.

Effort is the exception. On the 5.5 models effort can change from one message to the next without losing the cache, and thinking is billed as output, so effort is the cheapest lever inside a task. On older models an effort change rewrites the cache like a model change does.

Things that look like clean points and are not

A resumed session
claude -c and --resume bring back a conversation whose cache may still be warm. Only the first prompt of a genuinely new conversation counts.
/model
In an interactive session /model and /effort also save your default for every new session. agento never runs them for a per-task choice; it holds the cheaper setup for that task only, and a /model you type ends the hold.
Compaction mid-turn
Compaction does start the cache over, so the next prompt is a clean point. The turn already in progress keeps its model.
/agento new in a long context
Marking a new task by hand in a long, warm conversation would move all of it to another model. There agento offers /clear instead.

What a switch in the middle costs

Take a typical agent step on a 100k cached prefix: read the prefix from the cache, write 3k of new input to it, produce 1.5k of output. At list prices:

One stepOpus 5.5Sonnet 5.5Haiku 4.5
cache read, 100k$0.020$0.020$0.010
cache write, 3k$0.015$0.0075$0.0038
output, 1.5k$0.030$0.015$0.0075
total$0.065$0.0425$0.021

Opus 5.5 and Sonnet 5.5 read the cache at the same price, so Sonnet saves only on output and new input: about $0.0225 a step. A switch in the middle of a task writes the whole prefix into the new model’s cache, 100k at $2.50 per million, so $0.25 instead of a $0.02 read. That is $0.23 extra, once.2

2The built-in opusplan pays this cost every time: it plans on Opus and executes on Sonnet in the same context.

Ten steps is a short task, so why not switch anyway? Because the cheaper model is not guaranteed to finish in the same number of steps, and a long task is exactly where the prefix is large and the penalty grows with it. So the decision moves to the places where it is free: the start of the task, /clear, and subagents, which have their own cache.3

3Why the cache, not tool output, dominates the bill: “Token Reduction Is Not Cost Reduction”, arXiv 2607.12161.

Plan on Opus, write the code on Sonnet

A hard task on Sonnet or Haiku gets one hint: discuss the plan with Opus in plan mode. The trigger is either the rules (architecture and planning words) or the trained classifier’s plan-first answer. When you approve the plan, agento offers the handoff.

Subagents and the orchestrator

A subagent starts with its own empty cache and does not read the parent’s, so its model can be chosen freely. agento routes spawns by what the prompt asks for: reading and searching go to Haiku, well-specified code to Sonnet. It never raises a subagent above the model you are on.

With orchestrator mode on (the default), the main thread gets three named helpers and a short instruction on when to use them:

AgentModelJob
agento-scoutHaikuFinds code, reads many files, traces a call path. Never edits. Returns paths and line numbers, not file dumps.
agento-builderSonnetImplements a clearly specified piece of work against a given plan, then runs the checks. Stops and reports if the plan is wrong.
agento-checkerHaikuRuns tests, type checks and builds, and reports only what failed, with file and line.

When the trained classifier says a task starts with exploring, agento adds one line for the agent: send agento-scout first to find the files. Turning orchestrator mode on takes effect from the next session, because the system prompt is fixed when a session starts and changing it would break the cache.4

4Principle 7 below. The pane says so: “Orchestrator mode applies from the next session”.

When the agent goes in circles

A stuck agent is the most expensive agent: every extra step re-reads the whole context. The loop guard watches tool calls and raises one banner when it sees the same test failing a third time, the same spot edited three times within ten steps, or four tool errors in a row. It works in subagents too, and stays quiet for ten steps after it has spoken.

The classifier behind the hints

The question at a clean point is “what does this task need?”: a model tier, an effort level, whether to plan first, whether to start by exploring. Two things can answer it.

Built-in rules
Keywords in English and Russian, prompt length, planning and architecture words. Always available, instant, and the source of the model choice today.
agento-brain
An optional local daemon on a unix socket that serves the trained student, multilingual-e5-small. Median answer about 6 ms on an Apple-silicon Mac. Its plan-first and explore-first answers are used; its tier answer never decides on its own.

The plugin waits at most 400 ms for the daemon. On any error, a timeout or an answer it cannot parse, the rules answer instead, and the pane shows which one did.5 Why the tier answer is not trusted yet is on the Benchmarks page.

5Details: brain/README.md, training/README.md, and the GPU runbook, in Russian: docs/runbook-gpu.md.

Seven principles

Every hook is written against them, and the tests hold each one.

  1. The main model never changes mid-task. You are 40 steps into a refactor on Opus with a 150k context and the rules think the next prompt is light. agento says nothing: the switch would rewrite about 150k of cache, roughly +$0.35, to save cents per step.
  2. Inside a task, save without touching the main model. The Opus thread needs to read 30 files. With orchestrator mode on, agento-scout reads them on Haiku and returns a summary with paths and lines; the Opus cache is untouched.
  3. Never above your choice. You start a large refactor on sonnet·low. agento may suggest planning it with Opus, but it never raises the model or the effort by itself. What you picked is the ceiling.
  4. Nothing silently. Autopilot moved a light task to sonnet·medium. You see “agento: sonnet·medium for this task” with a button to go back and one to turn autopilot off, and the ledger records why.
  5. Fail-open. agento-brain is down or slow: after 400 ms the rules answer. A hook throws: the request goes on unchanged. Nothing agento does can block your turn.
  6. Dollars and limits, not tokens. The pane says “$6.71 measured” and “≈ $2.12 estimate”, never one for the other. A subscriber sees the weekly limit, with the rate fitted from their own history and labelled as an estimate.
  7. What agento adds to the prompt is fixed at session start. Turning on orchestrator mode mid-session changes nothing until the next session. Editing the system prompt mid-session would break the cache agento is trying to protect.

What leaves your machine

Nothing, unless you train. The audit reads the transcripts Claude Code already keeps on your disk and prints the report; the plugin keeps its ledger next to them. There is no account and no telemetry. The training pipeline is optional: it builds a dataset from your own history, scrubs it, and sends it only to a GPU machine you choose.

The screenshots on this site and in the README are rendered from a synthetic sample report or from aggregates. None of them contains a prompt, a project name or a path from anyone’s work.

Everything runs on your machine. No account, no telemetry, no analytics on this page.
