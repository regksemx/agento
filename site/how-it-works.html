How it works

One decision per task, made where it is free.

agento is a Claude Code plugin. Its hooks run inside Claude Code, see every prompt and every model request, and can add a status line, a banner above the prompt and a pane. It makes one decision at the start of a task, when changing the model costs nothing, and otherwise keeps out of the way: it routes subagents, watches for loops and counts the money.

01 Architecture

The hooks

  • prompt.submit decides whether this prompt starts a task and, if so, asks System 1 what the task needs. It can show a banner; it never sends anything for you.
  • turn.step runs before every model request. agento only reads the usage it returns, with one exception you switch on: autopilot's per-task hold, which sends that task's main requests on the cheaper setup it chose.
  • agent.spawn picks the model of a subagent. Subagents have their own cache, so this choice is always free: Haiku for exploring, Sonnet for well-described code.
  • tool.call feeds the loop guard (the same test failing, the same spot edited again, error streaks) and notices an approved plan for the handoff.
  • ui draws the status line, one banner above the prompt at a time and the /agento pane.

System 1

The classifier that answers “what does this task need?” is either the built-in rules-v1 (keywords, prompt length, planning words) or a small trained model served by agento-brain, a local daemon on a unix socket. The plugin waits at most 400 ms; any error or timeout and the rules answer. The pane shows which one is active.

02 The decision at a task start

What counts as a clean point

A model is cheap to change only when there is no warm cache to lose. agento treats these as task starts: the first prompt of a genuinely new conversation, the first prompt after /clear or a compaction, a prompt after the cache went cold (5 minutes on an API key, 1 hour on a subscription), and an explicit /agento new. Inside a task the verdict is still computed for the ledger, and nothing is acted on.

Hint or autopilot

By default you get a hint with its reason and an estimate, and you decide. With autopilot: clean-points agento applies the choice itself, but only for that one task and only where the switch is free, and tells you so with an undo button. The next clean point decides again.

The other hints

  • Plan with Opus (S2). A hard or planning task on Sonnet or Haiku gets “Discuss the architecture with Opus (plan mode)”. When the plan is approved: “Write the code on Sonnet, clean context”.
  • Context hygiene (S4). A new topic in a context over 60k, or any context over 150k: /clear, or compact keeping what matters.
  • Stuck agent (S7). The same test failing a third time, the same spot edited again, a streak of tool errors: [Stop] [Hint for the agent] [Continue].

03 Prompt-cache economics

The worked example

A typical agent step on a 100k cached prefix: read the prefix from cache, write 3k of new input to it, produce 1.5k of output. List prices as of 2026-10-05.

One stepOpus 5.5Sonnet 5.5Haiku 4.5
cache read, 100k$0.020$0.020$0.010
cache write, 3k$0.015$0.0075$0.00375
output, 1.5k$0.030$0.015$0.0075
total$0.065$0.0425 (−35%)$0.021 (−67%)

Opus 5.5 and Sonnet 5.5 read the cache at the same $0.20 per million tokens, so Sonnet saves only on output and new input: about $0.0225 a step. Switching mid-task writes the whole prefix into the new model's cache: 100k × $2.50/M = $0.25 instead of a $0.02 read, +$0.23 once. It pays off after about 10 steps, and only if Sonnet needs no extra steps. The built-in opusplan pays this tax: it plans on Opus and executes on Sonnet in the same context.

Where changing things is free

  • Effort on the 5.5 models. On Opus 5.5, Sonnet 5.5 and Fable 5.1 effort can change per message without losing the cache. On other models an effort change rewrites it too. Thinking is billed as output, so effort cuts the most expensive part of a step.
  • Subagents. A subagent has its own cache and does not read the parent's, so its model is chosen without touching yours.
  • Empty or cold caches. After /clear, after compaction, after the TTL. That is exactly where agento decides.

Sources: Token Reduction Is Not Cost Reduction (arXiv), Anthropic pricing and prompt-caching docs.

04 Seven principles, with an example each

P1 · never mid-task

The main model never changes mid-task. Automatically, never.

You are 40 steps into a refactor on Opus with a 150k context and the rules think the next prompt is light. agento says nothing: switching would rewrite ~150k of cache, about +$0.35, for a gain of cents per step.

P2 · save inside the task

Inside a task, save without touching the main model.

The Opus thread needs to read 30 files. With orchestration on, an agento-scout subagent on Haiku reads them and returns a summary with paths and lines; the Opus cache is untouched.

P3 · ceiling

Never above your choice.

You start a large refactor on sonnet·low. agento may suggest planning it with Opus, but it never raises the model or the effort by itself. What you picked is the cost ceiling.

P4 · visible

Nothing silently.

Autopilot moved a light task to sonnet·medium. You see “agento: sonnet·medium for this task” with [Back to opus·max] and [Turn autopilot off], and the ledger records why.

P5 · fail-open

On any error, Claude Code behaves as if agento were not there.

agento-brain is down or slow: after 400 ms the rules answer. A hook throws: the request goes on unchanged. Nothing agento does can block your turn.

P6 · dollars

Measure dollars and % of limits, not tokens.

The pane says “$6.71 measured” and “≈ $2.12 … estimate”, never one for the other. A subscriber sees the weekly limit; its “% per dollar” is fitted from their own history and labelled as an estimate.

P7 · stable prefix

What agento adds to the prompt is fixed at session start.

Turning on orchestration mid-session changes nothing until the next session: “Orchestrator mode applies from the next session”. Editing the system prompt mid-session would break the cache agento is trying to protect.

05 Safety lessons we learned

/model is not a per-task switch

In an interactive session /model and /effort also save your default for every new session. So agento never runs them for a per-task choice: it holds the cheaper setup for that task through turn.step, and the session's own model is never touched. A /model you type ends the hold.

Resume is not a clean point

claude -c and --resume bring back a conversation whose cache may still be warm. Only the first prompt of a genuinely new conversation counts; a resumed one also resets what the ledger knew about the cache.

Automatic compaction can land mid-turn

Compaction does start the cache over, so the next prompt is a clean point. But the turn in progress keeps its setup until that prompt decides again (P1).

/agento new on a warm context is not free

Marking a new task by hand in a long, warm conversation would move that conversation to another model. agento offers /clear there instead of switching.

Buttons never send a prompt for you

The handoff saves the plan, runs /clear and fills the input box with “Implement the plan in .agento/plans/…”. Enter is yours to press.

A judge is not a router

In published work, Opus asked to route from the start of a task guessed “needs the strong model” in only 7 of 147 cases. Judging a finished task is easier, but still not trusted: judge labels are checked against hand labels and replays (see Judges compared).
